## 机制沉淀(蒸馏素材)

- **两段式时序铁律:富集必须严格后置于 skeleton 终写**。skeleton 终写是整包重建(collect() 从零拼 payload),终写前的任何富集字段都会被抹;实测踩形:AI 富集腿在未 settle 载荷上就锁 latch,终写一抹即永失(latch 单向)。修法 = 两腿都等 `settled:true` 再 kick(发起笺原文如此,初版实现偏离即翻车,回读笺文才归位)。
- **引擎晚批注入形态(clean-chrome OnScripts 实测)**:脚本清单应答晚到时 start/idle 两桶同批注入(load 已完即立刻注 idle 桶);document-start 探针可晚到 readyState=complete 才跑(dbg `sk:inject:complete`),且 heavy 可能先于 skeleton 首写 attr 启动。推论:heavy 段对骨架缺席**不可一次性放弃**,要有界等 attr 首现(观察器兜住首写,heavySettleAwait 帽);「注入即同步看 attr 再决定退出」的形在晚批形态下必翻车。
- **跨脚本共存道**:同批两段各自 IIFE,不共享内存,唯一信道是 DOM attr(与三世界实测裁定同源:DOM 属性是唯一跨世界道);读-改-写必须在同一同步块(跨 tick 无交错,不丢写)。heavy 的 dbg 经 attr 增量并入 probe_debug(帽 48 条滚动)。
- **@name 沿用即原位替换**:骨架沿用旧单件 `@name google-search probe`,引擎 id = SHA256("namespace@name") 同 id,装机 replaced:true 原位换源,旧条目无残尸;heavy 新名新条目。多文件 install 一道装。
- **验收道省 quota**:heavy 逻辑面(main 世界)可在中性页(example.com)手布 attr + 分块注入全文复现(argv 128KB 上限,拆 4 块 window.__hvN 拼 (0,eval));/eval 是方言值语言不是 raw JS 道,别走错门。真机 google 配额窗内每跑都珍贵,逻辑 bug 先本地复现再上真机。
- **browse 消费面缺口(待 browse 批次)**:workspace.rs 成对判定硬编码 `probe.user.js` 单件名,两段式对从 `browse workspace list` 对册掉出(detect 热路径同源枚举);按 REQ-041 Notes「browse 侧另立批次」不在本笺修,workspace README 与 pair README 已注记。
